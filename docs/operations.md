# Запуск и эксплуатация

## Локальный запуск

Нужны Python 3.11+, `uv` и системная библиотека `libsndfile`; для MP3 может понадобиться `ffmpeg`.

```bash
make install
make env
make run
```

API будет доступно на `http://localhost:8000`, интерактивная схема — `/docs`. Создайте индекс после загрузки треков: `POST /index/rebuild`. Полный набор сценариев и примеры загрузки есть в корневом [README](../README.md).

## Конфигурация

Основные переменные окружения перечислены с комментариями в [`.env.example`](../.env.example). Параметры алгоритма задаются в `configs/config.yaml`; другой файл можно указать через `CONFIG_PATH`. Переменные окружения имеют приоритет над значениями файла.

- `DB_URL` задаёт базу данных. По умолчанию — SQLite в `data/recommender.db`.
- `FEATURE_SOURCE` выбирает `librosa` или `embedding`.
- `API_KEY` включает проверку ключа для изменяющих запросов. Пустое значение отключает проверку (подходит для локальной разработки).
- `API_PROTECT_READS=true` требует ключ также для чтения.
- `AUDIO_STORAGE` выбирает локальное хранилище или S3-совместимое; S3-параметры заданы в `.env.example`.
- `HIDDEN_SOURCES` задаёт источники, скрытые в выдаче.

## Docker и данные

`docker-compose.yml` запускает online API и PostgreSQL. Значения `.env` используются Compose; секреты и пароли следует заменить перед развёртыванием. При первом старте Postgres создаёт volume, поэтому изменение `POSTGRES_*` после его создания само по себе не меняет пользователя или пароль внутри существующей базы.

Миграции применяются сервисами при старте. Явный запуск: `make migrate`. Для переноса локальной БД в Postgres предусмотрена `make db-copy`.

## Мониторинг

- `GET /health/live` — процесс отвечает.
- `GET /health/ready` — готовность API и индекса.
- `GET /metrics` — метрики Prometheus.

Prometheus-метрики включают запросы по HTTP-методу, шаблону маршрута и коду ответа; гистограмму задержек; счётчики выданных рекомендаций; размер и сведения о загруженном индексе; стандартные метрики процесса. Счётчики хранятся в памяти процесса.

`LOG_LEVEL` задаёт уровень логирования, `LOG_JSON=true` включает JSON-строки. Для запросов журналируются маршрут, статус, длительность и `request_id`.

## Batch и расписание

Batch CLI запускается через `.venv/bin/python services/batch/main.py <команда>` или соответствующие цели `make batch-*`. Airflow доступен через `make airflow-up`; DAG описан в `airflow/dags/recommender.py`. После batch-пересборки работающему online-сервису можно передать новый артефакт через `POST /index/reload`.
