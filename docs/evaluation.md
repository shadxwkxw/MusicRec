# Оценка качества и тюнинг

## Метрики на лайках

Для каждого скрытого целевого лайка ранжируется список кандидатов. При `k=10` (значение по умолчанию):

- **Hit@k** — доля запросов, в которых целевой трек попал в первые `k` позиций.
- **MRR@k** — среднее обратное ранговое место целевого трека; если он стоит на первом месте, вклад равен 1, на втором — 1/2, а если он вне топ-k — 0.

Оценка ведётся отдельно по путям `track` и `user`. `best_score` — среднее MRR@k по доступным путям, это целевая величина при лайк-ориентированном тюнинге.

## Процедура проверки

Лайки пользователя делятся на обучающую и отложенную части; доля и seed задаются в `tuning.test_fraction` и `tuning.seed`. Для подбора по лайкам используется leave-one-out: один лайк скрывается, остальные строят запрос/профиль. Для финального отчёта тюнинг сравнивают на отложенных лайках с `content_only`, `same_artist`, `popularity` и точным математическим ожиданием случайной выдачи (`random`).

Целевая функция `tuning.objective` может быть `genre`, `likes` или `auto`. `auto` выбирает оценку по жанрам, если размеченного каталога достаточно, иначе использует лайки. Жанровая цель оценивает долю совпадения жанра; можно выбрать macro-среднее по жанрам или micro-среднее по трекам.

Результаты тюнинга доступны через `/automl/status`; `make batch-evaluate` строит отчёт для текущего индекса. Метрики малоинформативны при слишком малом числе отложенных лайков. Детали схемы разбиения и параметры приведены в корневом [README](../README.md#тюнинг-optuna).

## Поиск соседей — отдельное понятие

`cosine` и `euclidean` — метрики расстояния, используемые FAISS для поиска похожих треков. Это не метрики качества рекомендаций: качество оценивается Hit@k/MRR@k (или целевой функцией по жанрам).
